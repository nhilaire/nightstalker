# ADR 0001: Expo (CNG) or bare React Native

Status: accepted
Date: 2026-10-20
Decision: expo

> `Decision:` is `expo` or `bare`. `Status:` becomes `accepted` only after the user agrees.

## Context

Nightstalker is a faithful port of an Expo SDK 55 prototype (`C:/dev/Nightstalker`, Expo managed + Skia). The
approved PRD needs:

- **Rendering:** a 200 x 120 logical playfield scaled to the screen, ~8 pixel-art sprites redrawn every frame, up to
  ~100 square particles (invisible robot burst), blinking, halos, laser bolts. That is beyond what Views handle well,
  so **Skia** (`@shopify/react-native-skia`, Canvas) as in the prototype; it requires `react-native-reanimated` +
  `react-native-worklets`.
- **Input:** a joystick (pan) and a fire zone (taps) used **at the same time** by two thumbs, four fire modes:
  `react-native-gesture-handler` (as in the prototype).
- **Audio:** synthesised sound effects and a looping heartbeat at 6 tempos. The prototype used `expo-av` (removed
  in SDK 55+) with WAV data URIs built at run time. Port: generate the same WAVs **at build time** with a Node script
  from the prototype's synth code (committed under `assets/sfx/`, header test per the factory pattern), played with
  `expo-audio` + `expo-asset`. Haptics: `expo-haptics`.
- **Platform:** landscape locked (static `orientation: landscape` in the app config), immersive full screen (status
  and navigation bars hidden), AsyncStorage for scores and settings, `expo-localization` (factory i18n), Firebase
  Analytics + Crashlytics (React Native Firebase v26, opt-in).
- **Build:** local only, Windows, signed arm64 APK sideloaded; no EAS.

## Criteria

| Criterion | Weight | Expo (CNG + prebuild) | Bare React Native | Notes |
|---|---|---|---|---|
| All required libraries work with Expo prebuild / config plugins | high | yes | yes | Skia 2.6 + Reanimated 4 + worklets proven on SDK 57 by ganja-farmer; gesture-handler, expo-audio, expo-haptics, AsyncStorage are standard; RNFB has config plugins |
| Need to hand-edit native Android code continuously | high | no | no | nothing in the PRD touches native code |
| Custom native module (Kotlin/C++) needed | medium | no | no | game logic is pure TypeScript |
| Upgrade effort over time | medium | low (bump SDK, `expo install --fix`) | higher (Upgrade Helper diffs) | |
| Build simplicity on this machine (local Gradle) | medium | `build-apk.mjs` (prebuild + Gradle), proven on 5 games | Gradle directly | |
| Firebase setup effort | low | config plugins | manual Gradle setup | |
| Closeness to the prototype | medium | same framework (SDK 55 → 57) | port to bare | most UI code moves as is |

## Decision

**Expo SDK 57 with Continuous Native Generation**, rendering in a **Skia Canvas**, input with **Gesture Handler**,
sound with **expo-audio** playing build-time-generated WAVs.

1. Every library the PRD needs works with Expo prebuild; Skia + Reanimated on SDK 57 is already proven in this
   factory (ganja-farmer).
2. The prototype is already Expo: the port is an SDK upgrade (55 → 57) plus the factory overlay, not a rewrite.
3. No native code to maintain; upgrades and Firebase stay cheap.

## Consequences

- `android/` is generated by `npx expo prebuild` and git-ignored; native changes go through config plugins (none
  expected beyond Firebase and the factory overlay).
- `expo-av` is replaced by `expo-audio` (+ `expo-asset`); the synth moves from run time to a Node script
  (`npm run sfx`) whose output is committed; a Jest test checks every WAV header (`RIFF`, `WAVE`, `fmt `, `data`,
  not silent), and each sound logs its first load so logcat proves playback.
- `expo-screen-orientation` is not needed (static landscape orientation). Immersive full screen uses the factory
  `Screen` approach; `expo-navigation-bar` is added only if the bars cannot be hidden otherwise (decided in
  `/scaffold-app`).
- Known pitfalls from ganja-farmer: Skia needs Reanimated + worklets installed together; clear the Metro cache if a
  build bundles Skia without worklets.
- The engine stays pure TypeScript under `src/game/` with injected randomness for deterministic tests.

## Alternatives considered

- **Bare React Native:** works, but brings committed native code and manual upgrades for no benefit here.
- **Views + Reanimated instead of Skia:** too many moving elements and particles redrawn every frame; the prototype
  already proved Skia.
- **Keep run-time synthesis with data URIs:** fewer files, but data URI playback with expo-audio is unproven in this
  factory and the build-time WAV pattern has a header test that already caught a silent-game bug.
